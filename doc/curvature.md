# 曲率（curvature）怎麼算、怎麼看

lobj-view 右側物件卡片勾選 **curv** 後，會依每個頂點的曲率替模型上色。
這份文件說明背後的計算方式、畫面上每個選項的意思，以及使用時要注意的地方。
程式在 `web/src/curvature.ts`（計算）與 `web/src/props.ts`（套到模型上）。

---

## 1. 一句話版本

> 沿著每一條三角形的邊，看「法向量轉了多少」除以「邊有多長」。轉得越快，表面越彎。

平坦的地方，相鄰頂點的法向量幾乎一樣，曲率接近 0；
牙尖、牙齒邊緣、牙齦線這種轉折明顯的地方，法向量在很短的距離內大幅轉向，曲率就大。

---

## 2. 公式

演算法稱為 **Normal Variation（沿 edge）**，移植自
`AppLabelTooth/curvature/compute_vertex_curvature_normal_variation_edge.py`。

對 mesh 上每一條邊（頂點 v₁ → v₂）：

```
e  = v₂ − v₁          邊向量
Δn = n₂ − n₁          兩端單位法向量的差

κ_edge = (Δn · e) / |e|²
```

### 為什麼這樣算是對的

把表面想成很小一段圓弧。沿著方向 e 走一小段距離 |e|，法向量轉動的量約為 κ·|e|，
而且轉動方向就在 e 的方向上。所以 Δn 投影到 e 上，再除以 |e|²，剩下的就是這個方向的**法曲率**（normal curvature）κ。

### 驗算：球

半徑 R 的球，法向量朝外時 n = p / R，因此 Δn = e / R：

```
κ_edge = (e/R · e) / |e|² = 1/R
```

每一條邊都剛好得到 1/R。程式用 R = 5 的經緯球測試，結果正是 0.200。

### 單位

κ 的單位是「1 / 模型長度單位」。牙齒模型通常是 mm，所以是 **1/mm**。
它的倒數 1/κ 是**曲率半徑**：κ = 0.5 表示這裡彎得像半徑 2 mm 的圓。
圖例上的數字就是 κ，滑鼠移到圖例上會顯示對應的曲率半徑。

## 3. 三種模式

每個頂點連著好幾條邊，每條邊各有一個 κ_edge。三種模式是把這些值合成一個頂點值的不同方法：

| 模式 | 每個頂點取什麼 | 顏色 | 適合看什麼 |
|---|---|---|---|
| **凸凹**（預設） | 相鄰邊 κ_edge 的**平均**，保留正負號 | 藍 – 灰 – 紅 | 哪裡凸、哪裡凹 |
| **max \|κ\|** | 相鄰邊 \|κ_edge\| 的**最大值** | viridis（紫 → 黃） | 稜線、邊緣：只要有一個方向很彎就亮 |
| **min \|κ\|** | 相鄰邊 \|κ_edge\| 的**最小值** | viridis | 各方向都彎的點（例如牙尖頂）才亮 |

### 凸凹的正負號

法向量朝外時：

- **正（紅）= 凸**：牙尖、牙脊、牙齒邊緣
- **負（藍）= 凹**：牙齦線、窩溝、牙間
- **0（灰）= 平**

這是在 Python 版之外另外加的模式。Python 版只取絕對值，分不出凸凹；
對牙齒來說，牙齦線（凹）和牙齒邊緣（凸）都很彎，但意義完全不同，所以預設用凸凹模式。

> 如果某個檔案的法向量朝內，凸凹的紅藍會整個顛倒。

### max / min 的限制

- **min |κ| 不等於最小主曲率。** 馬鞍形的地方（一個方向凸、一個方向凹），中間一定有某個方向完全不彎，min |κ| 會接近 0。
- max / min 取的是絕對值，看不出凸凹。

這兩個模式保留下來，是為了和 Python 版（AI 前處理用）的結果對照。

## 4. 平滑（先平滑再算）

口掃 mesh 的邊長約 0.17 mm，掃描雜訊會讓法向量在小範圍內亂跳。
這些亂跳在曲率圖上會變成滿滿的紅藍斑點，蓋住真正的形狀。

「平滑」滑桿（關、×1–×20）會在算曲率**之前**，把每個頂點的法向量換成「自己 + 相鄰頂點法向量」的平均，再正規化，重複指定的次數。

- **頂點位置不動**，只平滑法向量。
- 只影響曲率顏色。畫面上的模型和 normal 線都不變。
- 次數越多，留下的凹凸尺度越大：×1–×3 去掉細碎雜訊，×10 以上只剩牙齦線、牙尖這類大結構。
- 球面上平滑 ×10 後，曲率仍是 1/R。均勻彎曲的表面不受影響，被壓掉的只有局部雜訊。

### 為什麼不平滑頂點位置？

一般 mesh 平滑（Laplacian、Taubin）是移動頂點位置。實測反而更糟：
頂點會沿著表面滑動，把三角形擠成細長形；邊長 |e| 變小，公式分母變小，κ 就爆大。

實測 `lower_00OMSZGW_.lobj2`（凸凹模式的 |κ|）：

| 處理方式 | p90 | p99 |
|---|---|---|
| 不平滑 | 1.68 | 6.1 |
| 平滑頂點位置 ×10（Laplacian / Taubin） | 1.28–1.58 | 6.9–7.4（變大） |
| 平滑法向量 ×1 | 1.28 | 4.0 |
| 平滑法向量 ×5 | 0.85 | 2.0 |
| 平滑法向量 ×10 | 0.67 | 1.4 |

## 5. 截斷百分位（色階範圍）

曲率的分佈尾巴非常長：同一個模型，中位數 |κ| 約 0.36，但最大的 1% 超過 6（多半是雜訊和破面）。
如果用「最小值到最大值」當色階範圍，幾乎整個模型都會擠在同一個顏色。

所以上色前會先截斷：超出範圍的值一律當作端點顏色。「截斷」滑桿（p50–p100）設定上界百分位：

| 模式 | 色階範圍 | 預設 |
|---|---|---|
| 凸凹 | ±（\|κ\| 的第 p 百分位），0 固定在中間的灰色 | p90 |
| max / min | 第 min(1, 100−p) 百分位 ～ 第 p 百分位 | p95（即 1%–95%） |

- 數值**越小**對比越強，細微的凹凸也會上色；數值**越大**，越接近原始範圍。
- max / min 調到 **p99.5** 就是 Python `clip_percentile` 的 0.5%–99.5%；p100 是完全不截斷。
- 三個模式各自記住自己的值；**雙擊滑桿**回到預設。

## 6. 和 Python 版（AppLabelTooth）的差異

| 項目 | Python | lobj-view | 原因 |
|---|---|---|---|
| 曲率公式 | κ = \|Δn·e\| / \|e\|² | 相同 | 公式正確（球面驗算 1/R） |
| 凸凹模式 | 無 | 有，且為預設 | 牙齒的凸與凹意義不同 |
| 尺度正規化 | 座標除以 x 方向標準差 | 不做 | 保留 1/mm 的物理單位；色階本來就依百分位決定，不受尺度影響 |
| 截斷 | 固定 0.5%–99.5% | 可調，預設凸凹 p90、max/min 1%–95% | 口掃資料尾巴太長，0.5%–99.5% 幾乎整個模型同色 |
| `normalize_curvature` | 有（固定常數） | 不需要 | 顯示時會再依範圍拉到 0–1，這一步對顏色沒有影響 |
| 平滑 | 無 | 可選，平滑法向量 | 壓掉掃描雜訊 |
| 去除重複邊 | `np.unique` | 不去重 | 內部邊會被兩個三角形各算一次：max / min 不受影響；平均只在模型邊界上有極小差異 |

## 7. 效能

- 第一次勾選時才計算，結果會快取，之後切模式、拖截斷滑桿都只是重新上色。
- 18 萬頂點、36 萬三角形：不平滑約 0.2 秒；平滑 ×5 約 0.8 秒；×20 估計 2–3 秒（未實測；在瀏覽器主執行緒上算，期間畫面會短暫停住）。
- 每個平滑次數的結果都會快取，切回算過的次數不必重算。

---

## 8. 看圖建議

1. 先用預設（凸凹、平滑關、p90）看整體。
2. 斑點太多 → 平滑調到 ×3 ～ ×5。
3. 想看更細的起伏 → 截斷往左拉（例如 p70）；被少數極值洗白 → 往右拉。
4. 要和 Python 前處理的結果對照 → 切 max 或 min，截斷設 p99.5，平滑關。
